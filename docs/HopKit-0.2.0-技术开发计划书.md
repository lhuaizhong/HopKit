## 1. 目标与范围

### 1.1 用户与工作流程

主要用户是网络工程师、桌面运维和设备现场维护人员，同时保留普通用户的简洁排障入口。围绕以下流程补齐工具：

1. 确认本机接口、出口及故障目标。
2. 找到设备，确认主机和服务的响应情况。
3. 观察路径及持续变化，用两端收发验证具体网络规则。
4. 查询设备状态、DNS 和应用层证据。
5. 保存目标、参数和结果，形成可分享的维护记录。

### 1.2 已有能力与本轮缺口

已有：网络排障、本机网络概览、多目标监测、Ping、Traceroute、TCPing、DNS、NTP、iperf3、FTP、TFTP、HTTP 文件服务、Wormhole、Syslog，以及中英文、两种外观、JSON/PNG 导出。

实现基线的主要限制：任务和参数只保留在会话；GUI 最多四个活动任务、四十项会话任务，后端事件队列最多 150 项；DNS 支持八种记录；HTTP/TLS 只发 HEAD、使用内置根证书、不使用系统代理；TFTP 为 512 字节块、单传输且文件上限约 32 MiB。源码位置见第 4 节。这些是设计输入，不代表需要整体重写。

## 2. 导航分类与查找体验

### 2.1 分类决策

按最新确认调整为四个一级分类：**常用工具 / 文件传输 / 专家工具 / 小工具**。常用工具保留日常诊断；多目标持续监测与临时日志归专家工具，TFTP、FTP、HTTP 文件服务与 Wormhole 归文件传输；新增的批量、协议及深入诊断工具归专家工具，计算和轻量系统辅助归小工具。

本轮保持四个一级分类，不继续增加“网络发现、设备管理”等分类。工具数继续增长时，可用用途标签筛选；避免分类过深。分类表示操作场景，不限制用户权限；专家工具也应提供可直接使用的默认参数。

| 分类 | 英文 | 工具及建议顺序 |
| --- | --- | --- |
| 常用工具 | Common | 网络排障、Ping、Traceroute、TCPing、DNS、iperf3、NTP |
| 文件传输 | File Transfer | TFTP、FTP、HTTP 文件服务、Wormhole |
| 专家工具 | Expert | 端口扫描、设备发现、TCP/UDP 调试、多目标持续监测、Syslog 临时日志；后续加入 MTR、SNMP、路径 MTU、DHCP 诊断、HTTP/TLS 诊断、DNS 高级诊断 |
| 小工具 | Utilities | 子网计算器、本机端口与连接、Wake-on-LAN |

“本机网络概览”继续位于网络排障首页，不新增同内容入口。FTP 与 HTTP 文件服务保持相邻。常用 DNS 与高级 DNS 使用同一协议核心，高级入口直接显示对比/连续查询配置。HTTP 文件服务和 HTTP/TLS 诊断必须使用不同名称和图标说明，避免用户误把启动服务当成访问诊断。

### 2.2 交互要求

- 侧栏顶部提供四分类切换，选中分类后仅列该类工具；第一次启动选择常用工具和网络排障。底部不放预览标识、版本号及本地优先提示，工具列表占满其余可用高度并独立滚动。记忆最近分类、工具及滚动位置；旧记录按稳定工具 ID 迁入当前分类并保留收藏/参数，新增分类的滚动位置初始为 0；如果工具已移除，回退到网络排障。
- 工具搜索覆盖全部分类，支持中文、英文、协议名及别名，例如“扫端口 / port scan”“抓 UDP / UDP / socket”“唤醒 / WOL”。结果展示名称、分类和一句用途；选择后切换到对应分类并聚焦工具。
- 搜索只匹配工具目录，不匹配日志、请求正文或历史秘密；不因搜索或切换页面发起网络探测。
- 收藏为全局快捷区，不单独占用一个分类。同一个工具可以同时出现在分类与收藏中，但共享同一工具 ID 和参数。默认只提供收藏能力，不把新工具自动加入收藏。
- 任务中心保持全局可达。后台运行的任务在分类按钮和任务中心显示数量，不能因切换分类失去停止入口；分类变化不取消任务。
- 上一任务目标、发现的设备、扫描端口可通过明确按钮传入其他工具。携带主机、端口、地址族、可适用的源地址；不会自动开始，也不会把 HTTP 路径当作主机。
- 已实现且通过基本验收后才注册导航入口；未实现功能只在计划书中出现。能力受限时显示限制和原因，不以空结果表示支持。
- 两种外观、中英文、键盘导航、搜索 Esc/Enter、焦点提示均需覆盖。以当前最小窗口 960×680、常见缩放及长英文名称检查侧栏和内容区，避免页面横向溢出。

### 2.3 建议代码结构与验收

新增 `src/tools/registry.ts` 维护稳定 ID、名称、分类、搜索别名、用途、能力需求和组件映射；新增 `src/components/navigation/` 拆出分类、列表、搜索与收藏。`App.vue` 保留页面组合，逐步移出工具专属表单及结果。

注册表只管理呈现，不作为后端输入白名单或能力判定的唯一来源；Rust 对请求独立校验。CLI 子命令名称不因导航分类改变。

验收：每个旧工具均可找到且参数往返保留；HTTP 文件服务位置正确；搜索跨分类、收藏去重、删除收藏、无结果和长文本正常；四任务运行时切换分类仍能停止；重启恢复导航但不自动重启任务。B01 可先用现有 localStorage 保存无秘密的 UI 偏好，目标收藏与历史由 X04 接管。

## 3. 版本与交付策略

### 3.1 版本编号

- 开发线从 `0.1.0-rc.2` 提升到 **`0.2.0-dev.1`**，表示新的功能集开始开发，不表示已完成全部计划。
- 每个可供测试的完整增量使用 `0.2.0-dev.2`、`dev.3` 等。功能范围冻结且主体完成后进入 `0.2.0-beta.1`，发布验收阶段进入 `0.2.0-rc.1`，验收完成后为 `0.2.0`。
- 不用 `0.1.0-rc.3` 承载本次大批功能扩展；已有发布标签、资产及历史记录保持原样。功能开发中依靠提交和工作包编号记录进度，无需每次提交都改版本。
- 本次落实开发版号及计划书；导航和协议功能按后续工作包逐项实现。README 中分别说明“当前源码开发版本”和“最近发布包”，不能将旧下载链接改成尚不存在的 0.2.0 资产。

### 3.2 同步位置与发布检查

同步 `Cargo.toml` 的 workspace version、`Cargo.lock` 三个 HopKit 自有包、`package.json`、`package-lock.json` 根包及 `src-tauri/tauri.conf.json`。应用展示和 CLI 读取实际构建版本，打包资产沿用 `hopkit-<version>-<platform>-<arch>`。

`CHANGELOG.md` 新增开发中条目，仅写已经完成的变更；README 与 RELEASING 更新源码状态，历史示例和旧包 URL 保留其原版本。检查 Windows/macOS 安装元数据能接受预发布版本，并核验同版本多构建的安装行为；必要的原生数字版本映射在打包层明确记录，不修改用户可见 SemVer。

版本验证应读取结构化元数据逐项对比，不能对整个仓库全局替换版本字符串。不得更新第三方依赖版本或伪造新版本构建产物。

## 4. 共用技术基础

### 4.1 当前架构与改动位置

| 位置 | 当前职责 | 本轮设计 |
| --- | --- | --- |
| `crates/hopkit-core/src/runtime.rs` | 共用 Request、运行分发、错误及结果封装 | 渐进加入工具配置、能力与统一校验；保留旧请求兼容 |
| `diagnostics.rs`、平台 ICMP 适配器 | Ping/Trace/TCPing | 抽出可复用探测选项，增加 DF、PMTU 错误及 MTR 所需信息 |
| `transport.rs` | 带期限、取消、源绑定的 TCP 操作 | 提供扫描/调试/代理共用连接能力，避免复制平台连接逻辑 |
| `network.rs` | 本机接口、默认路由和目标路由 | 独立邻居、连接、DHCP 适配器；统一能力与来源说明 |
| `dns.rs`、`native_http.rs`、`tftp.rs` | 现有协议实现 | 按 X01/X02/X03 增量扩展，共用现有独立对端测试 |
| `src-tauri/src/main.rs` | 任务、事件队列、启动和停止 | 统一预算、控制命令、持久历史；后续可拆为 `tasks/`、`commands/` |
| `crates/hopkit-cli/src/main.rs`、`text.rs` | CLI 参数和呈现 | 新增子命令模块，共用核心验证和状态语义 |
| `src/App.vue`、`src/components/` | 导航、参数、结果和任务界面 | 工具注册表、专属组件、类型及跨工具目标传递 |

### 4.2 请求、结果与事件

不要继续把每个工具的全部字段平铺进通用 Request。参考现有 monitor/wormhole 的嵌套配置，为新工具增加 `scan`、`discovery`、`socket`、`mtr`、`snmp`、`pmtu`、`dhcp` 等明确类型；执行前验证 tool/action 与配置匹配。保留旧工具字段的兼容适配，逐步形成内部 `ToolConfig` 联合类型。

每个工具至少定义：`Config`、可序列化脱敏快照、`Event`、`Stats`、`Result` 和确定性校验。前端定义对应联合类型，可先人工维护后以构建期生成辅助；不得将协议状态全面退化成 `Record<string, any>`。

| 共用字段 | 约定 |
| --- | --- |
| `tool` / `action` | 稳定机器标识，与语言和导航分类无关 |
| `schema_version` | 按工具版本化；不因应用版本升级统一修改旧协议 |
| `task_id` / `event_seq` | 会话与历史关联；事件序号单调递增 |
| `observed_at` / `duration_ms` | 观测时间 UTC；期限及间隔由单调时钟计算 |
| `execution_status` | 任务执行完成、失败、停止等；沿用现有 envelope 的兼容表示 |
| `diagnostic_outcome` | 工具特有判据，与执行状态分离；允许 unknown/partial |
| `local_endpoint` / `remote_endpoint` | 实际连接地址；可取得时记录实际源地址、scope 和接口索引 |
| `capabilities` / `limitations` | 平台能力、未完成项、预览截断或日志缺失，不隐藏 |

增加统一进度事件、累计统计快照和有界预览。最终统计在核心维护，不能通过 GUI 当前表格反推。批量结果大于预览预算时分页或落盘；“预览有 1,000 行”不能限制实际扫描结果或虚构完整性。

保留已有 CLI 退出码：0 完成且满足工具适用判据；1 未满足诊断判据；2 参数错误；3 本机权限/资源/能力问题；4 文件或输出错误；130 主动取消。新增工具必须明确自己的成功判据，例如扫描完成且没有开放端口仍可退出 0，WOL 退出 0 仅表示报文已发送，不证明设备已唤醒。

新增机器 ID 与最小结果契约建议如下，功能实现时冻结并纳入兼容测试；配置及事件字段可增量加入，破坏性调整须提升对应 schema：

| 编号 / 建议 tool ID | 关键配置 | 最小可交付结果 |
| --- | --- | --- |
| E01 `scan` | targets、ports、timeout、concurrency、rate、family、source | resolved_targets、planned/completed/cancelled、state_counts、逐端点证据或受管结果附件 |
| E02 `discovery` | range/interface、methods、ports、name_lookup | candidates、responders、unknown、observations、neighbor_sources、观察时间 |
| E03 `socket` | protocol、mode、endpoint、source、encoding、limits | sessions/datagrams、sent/received_bytes、send_errors、preview_dropped、正文记录策略 |
| E04 `mtr` | target、cycles/duration、interval、max_hops、family | target_outcome、hops/responders、sample_counts、rtt_stats、path_changes、gaps |
| E05 `snmp` | version、operation、oids、context、sample_interval；凭据另传 | varbinds/object_errors、engine 信息、interface_samples、discontinuities、limits |
| E06 `pmtu` | target、family、min/max_ip_bytes、retries | confirmed_lower、confirmed_upper、reported_mtu、probes、unknown_reasons；无法确定的值为 null |
| E07 `dhcp` | operation、interface、duration、expected_servers | config_source、lease、offers、server_ids、outside_expected、limitations |
| U01 `subnet` | operation、address/prefix、other、split_prefix | canonical_network、address_counts、ranges、contains/overlap、精确拆分/聚合结果 |
| U02 `connections` | protocol、family、port/pid/state、refresh | query_interval、endpoints、process_visibility、partial_errors |
| U03 `wol` | mac、destination、source、port、count、interval | attempts、sent、send_errors、actual_local_address；无自动 wake_success |
| X01 `http_check` | URL、method、connect_ip、sni、proxy、trust、limits | hops、stage_timings、TLS/证书、headers/body_preview、truncation、路径及信任说明 |
| X02 `dns_compare` / `dns_watch` | question、type、servers、transport、interval | 每解析器原始答案、normalized_diff、samples、changes、gaps；普通 `dns` ID 保留 |

路径 MTU 的 CLI 名称为 `mtu`、内部 ID 为 `pmtu`，不得因界面文字变化改 ID。已有 `http` 继续表示文件服务，新的 `http_check` 为诊断；X03 沿用 `tftp`。存储/报告不引入会自动执行网络操作的隐式工具 ID。

### 4.3 调度与资源预算

保留 GUI 四个活动任务上限；一个扫描/MTR任务内部管理其探测，不为每个目标创建一个顶层任务。建立应用级网络预算，多个 GUI 任务分享预算；独立 CLI 进程有自己的预算，不宣称跨进程全局限流。

以下为开发初始值，须在 beta 前测量并冻结；任何调整要更新帮助、校验和测试：

| 项目 | 建议初值与边界 |
| --- | --- |
| 扫描目标 | 单任务默认最多 4,096 个地址；IPv6 仅显式地址集合或邻居候选，不枚举 /64 |
| 扫描组合 | 默认最多 65,536 个主机×端口组合；端口去重，1～65,535；超过限制须缩小或分批 |
| 并发连接 | 默认 32/任务，最大 128/任务；GUI 全局最多 128 个探测连接 |
| 探测速率 | 扫描/发现默认不超过 100 次/秒/任务，GUI 合计 200 次/秒；重试同样计入 |
| 有界缓存 | 独立累计统计；GUI 专属表格预览建议 1,000 行以内，详细记录分页，字节大小也必须有界 |
| 交互收发 | TCP 默认最多 16 个会话；UDP 不保证交付，发送频率和报文总量可设上限 |
| 可取消 I/O | 新增自有 socket I/O 每 50～100 ms 检查取消；目标停止延迟一般不超过 1 秒 |
| 系统查询 | 查询超时建议 5 秒；不可中断调用放独立有界工作线程，注明最坏停止时间 |

吞吐量测试另有大流量语义，不用扫描的每秒探测预算限制 iperf3。对持续任务做 CPU/内存/文件增长测量，定义可重复的测试环境，不以某台机器的瞬时数值作为跨平台保证。

### 4.4 平台能力、接口与依赖

新增能力查询记录：支持/不支持/需要权限/部分支持、适配器名称、可绑定的对象、可观察信息及平台限制。网络行为优先使用 Rust 协议和系统 API；已有系统内置查询可继续使用，必须固定参数、设置超时、按结构化格式或明确版本解析。

Windows 邻居和连接查询优先 IP Helper；macOS 先验证系统路由接口、公开可用 API 或自带查询命令的实际权限及输出，再定适配器。不能将“macOS 编译通过”当作读取全部进程 socket 的证明。新工具不得依赖用户安装 nmap、nc、mtr、Net-SNMP、curl、OpenSSL、iperf3 等可执行程序。开发互通测试可使用独立对端。

源 IP 绑定和固定接口绑定是不同能力，分别声明。DNS 查询、代理连接、IPv6 scope 和多网卡要记录实际行为；不支持时拒绝或明确跳过，不能默默换出口。依赖新增前验证 Rust 工具链兼容、三个目标平台、取消能力、维护状态、分发体积和许可，并固定锁文件；协议不适合从零实现时选可审查的库。

### 4.5 凭据与远端内容

新功能使用运行凭据对象，与可序列化配置分离；SNMP community、认证密钥、代理密码等不能进入事件、请求快照、错误日志、CLI 进程参数或历史。CLI 通过专用环境变量、交互或受控输入获取。初版不持久保存秘密；如未来接入系统凭据库需独立工作包。

远端主机名、证书、DNS/TXT、SNMP 字符串和任意报文都是不可信展示内容，始终转义并设大小限制。报文正文和业务日志可包含秘密，默认只保存元数据；完整正文落盘、导出由用户在相关操作中明确选择，并提供脱敏预览。执行时使用的 URL 查询参数可保留在内存，但继续从历史快照和常规报告排除。

## 5. 专家工具开发规格

### E01：TCP 端口扫描

**场景与范围：** 对一个或一组明确目标检查 TCP 服务。首版为 TCP connect，不做原始 SYN、UDP 扫描、操作系统指纹、漏洞脚本或广泛服务探测。单主机多端口先完成，再扩展有限地址集合；批量输入由核心统一展开、校验和去重。

**参数与界面：** 主机/IP、端口列表及范围、常用端口预设、超时、并发、速率、地址族、可适用的源地址。预设包含 Web、SSH、RDP、DNS/TCP、邮件等，并标注“常见端口用途”，不把端口号当成实际服务身份。域名解析后的候选 IP 在开始前或目标事件中明确展示，结果按 IP 分列；运行中不无提示重新解析目标。

**实现：** 新增 `scan/`，复用 `transport.rs` 的连接、期限和源绑定；工作池和令牌桶或等价的有界速率控制按第 4 节预算运行。M2 使用公平轮转与等间隔放行，避免突发。不写“每端口创建一个系统线程”。取消后停止新调度，关闭活动连接，返回已完成项及剩余数量。

**结果：** 每项包含目标、端口、状态、耗时、实际源/目标地址和错误证据；状态至少为 `open`、`refused`、`timeout`、`unreachable`、`local_error`、`cancelled`。`timeout` 不直接重命名为 filtered，拒绝也不作为一定来自目标本机的结论。扫描完成但零开放端口仍为一次有效扫描。服务 Banner 可列后续可选能力，不作为首版默认网络行为。

**CLI 草案：** `hk scan tcp 192.168.1.10 --ports 22,80,443,3389 --concurrency 32 --rate 100`；新增参数帮助及 JSON/JSONL，保留 `hk tcping` 原语义。

**验收：** 独立 TCP 对端建立开放、明确拒绝、超时注入及错误地址场景；核对重复端口和范围边界、双栈多地址、源地址、中文导出。超时用可控适配器或隔离网络模拟，不假设任意公网 IP 一定超时。覆盖 65,535 端口号、空列表、超预算组合、四任务公平性、取消、GUI 切页及部分结果。

### E02：局域网设备发现、邻居信息与冲突线索

**场景与范围：** 找到同一现场网段中的响应设备，并将其送往扫描、Ping、Web/TLS、SNMP。首版 IPv4 地址段主动探测；IPv6 展示邻居及明确指定的有限候选，不遍历巨大前缀。发现到的响应是证据，未响应不等于离线，也不证明地址可分配。

**输入输出：** 选择接口、CIDR/起止地址、ICMP/TCP 探测组合和少量候选端口。默认只建议所选接口的实际网段，不自动扫描所有私网或公网。展示 IP、响应方法、首次/最近响应时间、响应耗时、邻居状态，以及可取得的 MAC、PTR 名称和厂商提示；字段均附来源。名称解析采用低并发、有超时的可选阶段，不能阻塞设备出现。

**实现分步：**

1. 实现邻居表只读适配器和有限候选生成，保留接口索引、观察时间及邻居状态。
2. 复用 E01/ICMP 的有界调度做主动发现，更新邻居观测。不能因缓存中有条目就认为本次在线；陈旧缓存独立标识。
3. 权限与平台允许时增加主动 ARP/ND 验证；不支持时展示缺少的能力，不静默安装驱动或启动高权限助手。
4. 同一 IP 在同一链路上观测到不同 MAC 时给出“地址变化/冲突线索”，保留时间和证据；Proxy ARP、VRRP、网卡切换等也可能产生变化，不能直接判定冲突。专门的 ARP Probe 依 RFC 5227 单独验收。

MAC 通常只对本地二层邻居有意义，跨路由看到的下一跳 MAC 不能当成远端设备 MAC。厂商信息作为可选离线 OUI 数据集实现，先审查数据来源与分发条款；随机/本地管理 MAC、未知前缀不推断厂商，不发起在线厂商查询。

**CLI 草案：** `hk discover 192.168.1.0/24 --interface <接口> --methods arp,icmp,tcp --ports 80,443`；接口标识在各平台帮助中说明，不把跨平台接口名称视为相同格式。

**验收：** ICMP 禁用但 TCP 响应、只有邻居缓存、缓存过期、无 MAC、PTR 超时、多网卡和路由目标；/31、/32、不连续范围和地址溢出；IPv6 候选去重及 scope；重复地址、Proxy ARP/虚拟 MAC 模拟与真实设备验证。发现结果一键传递目标时保持地址及适用源参数，不自动探测。

### E03：TCP/UDP 调试助手

**场景与范围：** 在两端建立可观察的通道，验证出入方向的 ACL、防火墙、NAT 和设备原始报文。支持 TCP client/listen、UDP send/listen；首版不做远程命令执行、通用端口转发、SOCKS 代理服务器或任意脚本插件。

**界面与参数：** 连接/监听模式、目标/监听地址与端口、源地址、超时、文本/HEX、UTF-8 等明确编码、换行选项、定时发送间隔和次数；显示实际监听及设备应连接的地址。默认不开自动回显，回显须设置来源和速率限制；UDP 不做无限制广播回显。监听来源 CIDR 沿用现有服务配置习惯。

**实现：** 新增 `socket_tool/` 和运行期控制对象，参考 monitor/wormhole 的 control 模式。Tauri 的发送命令必须引用本机 task_id，并在 Rust 再校验任务模式、会话、长度及生命周期；任务已停止不能发送。TCP 为字节流，UI 的一次读取不称为一条业务消息；UDP 保留每个数据报的边界。TCP 会话有稳定编号，断连、半关闭、发送失败分别记录。

**结果与预算：** 双向记录相对时间、源/目标、会话/数据报、方向、字节数和有限内容预览；HEX 是原始字节的确定性呈现，乱码不能替换掉原始数据。默认单次发送上限 64 KiB，UDP 还需按地址族和实际协议上限校验；实时预览默认 1 MiB 总字节预算，丢弃预览有计数。可选择落盘并设置容量上限；默认不把正文写入通用历史。UDP 发送成功只表示本地交付，未回包不能证明端口关闭或对端未收到。

**CLI 草案：** `hk socket tcp connect 192.168.1.10 9000`、`hk socket tcp listen --listen 0.0.0.0 --port 9000`、`hk socket udp send 192.168.1.10 9000 --hex 010203`；CLI 输入在交互模式或 stdin 读取，二进制输入与 JSONL 输出不得混用同一数据通道而破坏格式。

**验收：** 独立对端验证 TCP 分段/合并读取、多个会话、半关闭、二进制零字节、UTF-8 截断、UDP 空报文与多报文、IPv4/IPv6、来源限制、端口占用。停止和退出关闭所有连接；发送队列满时有可解释反馈；高频收包不阻塞 UI，错误格式 HEX 在发送前拒绝。

### E04：MTR 持续路由诊断

**范围：** 首版 ICMP、IPv4/IPv6；在现有 Trace 基础上实现持续逐 TTL 观测，不调用外部 mtr。TCP/UDP MTR 作为后续协议模式，必须单独验证 ICMP 引用匹配及权限，不能把 TCPing 加上 TTL 当成完整 TCP MTR。

**参数：** 目标、地址族、间隔、每轮最大跳数、超时、轮数/持续时间，以及经平台证实可用的源绑定。DNS 反查默认可关闭，独立低并发完成。每轮探测受总速率预算控制；上一轮过慢时不无限堆积，也不补造样本。

**结果：** 按 TTL 展示多响应地址、发送、响应、超时、最近/最小/平均/最大延迟及抖动定义；延迟仅统计有效响应。目标到达率与各跳响应率分开。停止保留累计统计、观测窗口及路径变化时间，不将负载均衡形成的多个地址拼成已经证明的唯一物理路径。

MTR 首版抖动定义为同一 TTL、同一响应者在连续有效探测中的 RTT 差绝对值均值，单位 ms；跨超时、采样缺口或响应者变化不连接计算，少于一对有效相邻样本显示无数据。此值是 RTT 变化指标，不称为单向网络抖动；若后续增加 P95，记录具体分位数算法和有效样本数。

**关键语义：** 中间跳“未回应探测率”不等于转发丢包率；下一跳和目标正常时不能指责该中间设备。不同 TTL 的往返延迟差也不等于单链路延迟。ECMP、往返路径不对称和 ICMP 限速均列入报告限制。首版不宣称 Paris traceroute 或固定流标识能力。

**实现：** 新增 `mtr/`，复用平台 ICMP 协议而非复用现有 Trace 的最终汇总结构；并发探测必须以地址族、目标、标识符、序号和可用引用字段匹配，避免不同任务串包。每跳保存多个响应者及有界样本，累计指标独立。前端提供表格和变化时间线，先保证语义，再决定是否增加复杂图表。

**CLI 草案：** `hk mtr example.com --cycles 100 --interval-ms 1000 --max-hops 30 --format jsonl`。

**验收：** 可控多跳样本与真实隔离路由网络分别验证；覆盖中间全不回而目标可达、部分限速、多响应地址、路径变化、无法到达、IPv6、探测串包、取消和休眠。提供至少两小时有资源记录的运行证据，暂停/休眠缺口不计丢包；模拟拓扑不能代替真实逐跳互通。

### E05：SNMP 只读查询与接口观察

**子任务：** E05-A 完成 v2c GET/GETNEXT/GETBULK 和 WALK；E05-B 完成 v3 USM；E05-C 完成设备概览与接口观察。首版界面及 CLI 不提供 SET，避免把查询工具扩展为配置管理。v3 是本轮目标，不能仅支持 v2c 却统称已完整支持 SNMP。

**输入：** 设备地址、端口 161、版本、超时/重试、数值 OID/内置常用名称。v2c community 无默认明文写入配置；v3 提供用户名、context、认证/加密方式及运行凭据，清楚展示实际启用的安全级别，不静默降级。

建议初始默认：单次响应超时 1,000 ms、额外重试 1 次、接口采样间隔 2 秒；禁止同一设备的上次采样未完成时无界排队，丢失采样显示缺口。高延迟设备可调整，WALK 仍受总期限和结果预算约束。

**实现：** 评估可嵌入 Rust 的协议库，验证 BER、v3 engine discovery、engine boots/time、Report、认证失败和取消；若所选库不能可靠支持 v3，先完成候选验证再锁定，不能把系统 Net-SNMP 当作运行依赖。优先支持 SHA-2 认证和 AES-128 privacy，常见旧设备算法单独列兼容配置；具体组合以互通验收清单为准，不能在 UI 列出库未实现的算法。

**WALK 边界：** 子树必须有终点，OID 严格前进；处理 endOfMibView、noSuchObject、noSuchInstance、tooBig 和不符合预期的响应。默认最多 10,000 项、4 MiB 解码结果及 60 秒总期限，可收紧；GETBULK 设置有界 max-repetitions，异常响应不得造成无限循环。对象错误与整次传输错误分开。

**设备概览与接口：** sysName、sysDescr、sysObjectID、sysUpTime；IF-MIB 的名称/别名、管理/运行状态、速率、流量、errors/discards。优先使用 64 位 ifHCInOctets/ifHCOutOctets；序列化为十进制字符串或前端 BigInt，避免 JavaScript 丢失精度。用两次有效采样及实际间隔计算速率；设备重启、计数回绕、ifCounterDiscontinuityTime 变化标记数据间断，不产生负速率或峰值。厂商 CPU/温度等不通用字段后续通过明确模板增加。

**CLI 草案：** `hk snmp get 192.168.1.1 1.3.6.1.2.1.1.3.0 --snmp-version 2c --community-env HOPKIT_SNMP_COMMUNITY`；`hk snmp walk ...`、`hk snmp interfaces ...`。使用 `--snmp-version` 避免与全局程序 `--version` 产生歧义。

**验收：** 开发用独立 Net-SNMP 对端及至少两种真实设备；v2c/v3 正常、凭据错误、引擎时间变化、不支持 OID、空子树、tooBig、OID 不前进、畸形 BER、超时重试和取消。以已知 Counter64 序列核对速率与断点。快照、stderr、JSON/PNG/HTML、持久存储均检查不含 community/密钥。未提供完整 MIB 编译器时，数值 OID 和内置符号表的支持范围须明确。

### E06：路径 MTU 探测

**问题定义：** 当前 Ping 支持包大小，但尚不能保证禁止分片。新工具测量特定目标、源地址、地址族及时间窗口下的探测边界，不直接修改网卡 MTU 或系统路由。IPv4 和 IPv6 分别实现，不把 IPv4 的 DF 标志套到 IPv6。

**参数：** 目标、IPv4/IPv6、源地址能力、候选 IP 包总长度上下限、重试次数和每次/总超时。GUI 同时展示 IP 总长度、IP 头、ICMP 头和 payload；IPv4 无选项的 ICMP 探测通常为 payload+28，IPv6 无扩展头通常为 payload+48，若使用其他头部须按实际计算。

**算法：** 先用小包建立基线，再做有界候选搜索与重复验证。只有明确的 fragmentation-needed/Packet Too Big 或本机 EMSGSIZE 等证据才能收紧确定的过大边界；超时记为 unknown，有限重试后返回部分区间，不把超时机械当成 MTU 太小进行二分。保留最大已验证成功长度、最小明确失败长度、设备报告的 next-hop MTU 和全部依据。若所有候选成功，只能说“至少支持上限”，不能声称精确 PMTU。

**平台：** Windows 为现有 ICMP API 加入 IPv4 DF 选项并保留过大错误信息；macOS/Linux 为 socket 和错误解析建立对应适配。IPv6 验证源端分片控制及 PTB 取得方式；做不到时返回 unsupported/partial，不自动回退成普通大包 Ping。

**CLI 草案：** `hk mtu example.com -4 --min 576 --max 1500 --retries 3`；`min/max` 单位统一为 IP 包总字节数。

**验收：** 构造 MTU 1500/1492/1400 的隔离路由环境，核对禁止分片的实际报文；大包因 ICMP 过滤超时、路径变化、本地报文过大、IPv6 PTB、无目标回包等情况分别显示。通过对端抓包验证实际分片行为，不能仅靠本机返回“成功”。报告写明“ICMP 探测结果”，不将其自动等同于所有 TCP/UDP 流量的有效载荷上限。

### E07：DHCP 诊断

**子任务：** E07-A 只读本机 DHCP/静态配置与租约信息；E07-B 在用户选择的接口主动发现 DHCPv4 服务器。首版不提供 DHCP 服务端、不替系统续租/释放、不修改地址配置，不将 DHCPv6/RA 包含在 DHCPv4 的验收声明中。

**只读视图：** 展示接口是否 DHCP、可取得的服务器地址、租约开始/到期、掩码、网关、DNS、搜索域及数据来源。系统不给出的字段显示 unknown，不以配置文件陈旧值冒充实时数据。

**主动发现：** 指定接口，发送有限 DHCPDISCOVER 并收集 DHCPOFFER，显示 server identifier、实际报文来源、yiaddr、租期、掩码、路由器、DNS 和可取得的 relay 信息。默认 5 秒收集窗口、最多 3 次发送；事务 ID、chaddr/client-id 及接口必须可关联，不能收录其他主机的 Offer。

工具不发送 DHCPREQUEST/RELEASE/DECLINE，不申请或替换本机租约；但 DISCOVER 可能让服务器临时保留一个 Offer 地址，帮助中如实说明。多个 Offer 可来自合法冗余；只有用户提供预期服务器清单时才能标记“清单外服务器”，不能自动定性为恶意 DHCP。

**平台难点与先行验证：** UDP 67/68、广播出接口、系统 DHCP 客户端占用及收包权限在不同平台有差异。先制作本机实验原型验证，再决定系统 API、UDP socket 或可选特权收包适配；禁止停止系统 DHCP 客户端来腾端口，也不能用任意高端口应答作为标准设备兼容证据。权限不足时保留 E07-A，并清楚标记主动发现不可用。

**CLI 草案：** `hk dhcp inspect --interface <接口>`、`hk dhcp discover --interface <接口> --duration 5 --expected-server 192.168.1.1`。

**验收：** 独立 DHCP 服务端隔离网络，单/多服务器、无 Offer、relay、多网卡、错误事务、截断和重复选项、端口冲突及权限不足。抓包证明未发送 REQUEST/RELEASE/DECLINE，本机地址、租约和网络连接保持可用。物理网络中的真实设备互通为主动发现发布门槛。

## 6. 小工具开发规格

### U01：IPv4/IPv6 子网计算器

**范围与界面：** 输入地址/前缀或 IPv4 点分掩码，展示标准化网络、前缀、掩码、地址范围、地址总数、反掩码和可复制表达式；支持判断某地址是否属于网段、两网段包含/重叠、拆分为指定前缀。聚合先实现精确可聚合网段，不把超网覆盖中的空洞隐去。

**地址语义：** IPv4 /31 按点到点用途解释，/32 为单地址，不套用统一“总数减二”。普通广播子网给出常见主机范围，并说明地址可用性仍受配置影响。IPv6 无广播，不输出 IPv4 广播地址，也不自动扣除首尾地址。超大地址数量用整数/十进制字符串表示，前端不得通过浮点数计算。校验非连续掩码、前缀边界、地址溢出和超过显示预算的拆分。

**实现与 CLI：** `subnet.rs` 复用已引入的 `ipnet`，纯函数离线执行。有限计算不占用长期网络任务名额，但复用结果协议和导出。CLI 草案：`hk subnet inspect 192.168.10.25/24`、`hk subnet contains 192.168.10.0/24 192.168.10.25`、`hk subnet split 192.168.10.0/24 --prefix 26`。contains 为 true 退出 0、false 退出 1，参数错误退出 2。

**验收：** 已知 /0、/31、/32、IPv6 /0、/64、/127、/128 和非字节边界样本；与独立标准库结果核对。使用生成样本验证包含/重叠对称性、拆分无丢失不重叠及精确聚合；全程无网络请求，批量拆分超预算在分配内存前拒绝。

### U02：本机监听端口与连接查看器

**范围：** 只读 TCP/UDP 端点和 TCP 连接；显示协议、地址族、监听/连接状态、本地与远端地址、PID、可取得的进程名，按端口、地址、进程和状态过滤。UDP 不伪造 TCP 状态。默认手动刷新，自动刷新建议 2 秒且不允许查询重叠。

**平台：** Windows 优先 `GetExtendedTcpTable`/`GetExtendedUdpTable` 加进程元数据；macOS 先验证系统 API 或自带查询工具的覆盖范围与权限。权限不足、进程刚退出、PID 复用等情况保留端点观测，进程字段可未知。快照附查询起止时间，不承诺所有表项原子一致；地址族和通配地址按实际值呈现。

**联动：** HopKit 服务报告 ADDRESS_IN_USE 时，允许打开预填端口过滤的查看器。只有明确追踪到本应用 task_id 的监听才能链接任务，不把碰巧同端口的进程认成本应用任务。不提供一键杀进程、释放端口或修改防火墙。

**CLI 草案：** `hk connections --listening --port 8080 --format json`。进程完整路径默认不加入通用报告，可按需查看或脱敏。

**验收：** 独立进程创建 IPv4/IPv6 TCP/UDP 监听与连接，逐项核对端口、PID 和状态；短连接/进程退出竞态、非管理员、非当前用户进程、重复刷新与取消。查询失败不能显示“系统没有监听端口”，部分支持需显式标注。

### U03：Wake-on-LAN

**范围：** 输入 MAC、IPv4 目标广播/单播地址、UDP 端口、发送源 IP、重复次数/间隔，发送 Magic Packet。支持常见 MAC 分隔格式并标准化；拒绝广播/组播 MAC 等不适合作为目标的输入。默认端口 9、3 次、间隔 200 ms；用户可修改，默认不提供持续无限发送。

**实现与行为：** 构造 6 个 FF 字节加 16 次目标 MAC，总计 102 字节；socket 显式开启广播，并根据实际接口前缀建议广播地址，不默认假定所有网卡都是 /24。指定源 IP 只保证源绑定能力，实际出接口仍需验证。路由器未转发定向广播、设备未启用 WOL 等情况以限制说明呈现；首版不做跨公网唤醒服务。

**结果与 CLI：** 记录目标 MAC、报文目的地址、源地址、已发送次数、发送错误和时间。`hk wol AA:BB:CC:DD:EE:FF --broadcast 192.168.1.255 --port 9`；成功只表示发送完成。可选后续 Ping 检查为独立明确操作，即便有回复也不直接证明回复来自该 MAC。

**验收：** 独立 UDP 接收器验证精确字节、重复次数、接口选择和发送间隔；非法 MAC、无广播能力、无效源 IP、发送失败与取消。补充至少一台配置好的真实设备唤醒记录；接收器收到报文不能代替实际唤醒验收。

## 7. 现有能力扩展

### X01：HTTP/TLS 高级诊断

**入口与共用：** 专家工具新增 HTTP/TLS 诊断；常用工具的综合排障继续默认使用简洁检查，并可进入高级视图。共用 `native_http`/TLS 核心，不复制两套证书校验逻辑，不改变 HTTP 文件服务入口的用途。

**X01-A 证书与连接详情：** 展示叶证书主题、颁发者、SAN、有效期及剩余天数、指纹、服务器提供的证书链、校验结果、TLS 协议/密码套件、实际地址及阶段耗时。服务器提供的链与实际构建的信任路径分开表达；若库未暴露信任路径，不伪造完整链。证书尚未生效、过期、名称不符、缺中间证书、未知根和系统时间问题分别记录证据，失败也尽可能保留服务器已提供的公开证书信息。

**X01-B 请求与目标控制：** 保留 HEAD 默认，显式提供 GET、有限响应头/正文预览和重定向链。GET 默认最多保留 256 KiB 解码后正文，同时限制线上字节、解压后字节、头部和总时长；截断不称为完整下载。正确处理 Content-Length、chunked、关闭分隔和 HEAD/204 等无正文语义，不把压缩炸弹或超大长度读入内存。HTTP/2/3 待后续，不将 HTTP/1.1 成功标为所有协议正常。

允许覆盖连接 IP 和 TLS SNI，但 URL authority、Host、SNI、连接 IP 分别展示；默认 SNI 和证书名称校验遵循逻辑主机，用户覆盖时明确显示实际验证名。覆盖 IP 的作用域为初始主机，跨主机重定向重新按对应主机解析，不能把所有跳转强制送到一个 IP。保留 IDN、IPv6、凭据拒绝、跨源敏感头清除和 HTTPS 降级限制。

**X01-C 代理和信任对比：** 首版支持显式 HTTP 代理及 HTTPS CONNECT，随后支持 SOCKS5，并明确 DNS 在本地还是代理侧解析；支持直连/指定代理的两次独立观测，记录各自路径和时间，不保证两次请求使用同一 CDN 节点。源绑定在代理模式只约束到代理的连接，不能控制代理到目标的出口。

系统代理、PAC/WPAD 与企业 CA 单独暴露能力，不宣称显式代理就等于浏览器路径。首版默认继续内置根，可提供“系统信任根/显式 CA”选择并记录；加载系统根不等同于实现系统所有企业策略或在线吊销判断。PAC 执行、代理集成认证及浏览器会话不作为 0.2.0 门槛。跳过校验依旧醒目标记，不能输出证书正常结论。

**CLI 草案：** 保留 `hk http serve`，新增 `hk http check https://example.com/ --method GET --connect-ip 192.0.2.10`；`--sni`、`--proxy`、`--trust-store` 有独立帮助，秘密由运行凭据传递。

**验收：** 独立 HTTP/TLS/代理对端覆盖名称不符、过期、尚未生效、企业 CA、缺中间证书、HEAD 与 GET 不同、分块/压缩/畸形响应、循环重定向、跨源凭据、407、CONNECT 失败和 SOCKS DNS 模式。校验证书详情不能改变正常校验结论；URL 查询、Cookie、Authorization、代理凭据不出现在常规历史/报告。

### X02：DNS 高级诊断

**现状复用：** 当前已有 A/AAAA/CNAME/MX/TXT/NS/PTR/SOA 及 UDP 截断后的 TCP 回退，不能把 TCP 回退再次作为新功能宣称。常用 DNS 继续保持简单查询；专家工具增加多服务器对比和连续观察。

**X02-A 记录与控制：** 新增 SRV 的 priority/weight/port/target、CAA 的 flags/tag/value；补充直连 DNS 的 IDN 标准化、IP 到 PTR 名称转换入口、显式 UDP/TCP 选择。既有压缩名称、RR 长度和随机报文验证保持严格。系统解析不提供原始 RR/TTL 的字段应为 unknown，不给出虚构 TTL。

**X02-B 多服务器对比：** 一次最多四个指定解析器，可加系统地址解析视图；请求问题和记录类型一致，分别展示 RCODE、记录、TTL、耗时、传输和响应标志。比较忽略 RR 顺序，保留 TTL 差异和 CNAME 链；区分 NXDOMAIN、NOERROR 无记录、SERVFAIL、超时。系统地址解析与原始 RR 查询口径不同，不能简单对齐为相同测量。不同结果可能是分区解析/CDN，不自动判某服务器错误。

**X02-C 连续查询：** 默认间隔 5 秒，可设时长、次数和变更记录；观察记录集、RCODE 和延迟变化，支持中断/恢复标记和有界历史。TTL 倒计时、缓存及权威值的来源单独说明，不声称本工具请求能刷新全网缓存。解析器列表默认由用户选择，不因打开页面向公共 DNS 发送请求。

**CLI 草案：** 保留 `hk dns <name> <type> -s <server>`；新增 `hk dns-compare example.com A --server 192.168.1.1 --server 192.168.1.2`、`hk dns-watch example.com A --server 192.168.1.1 --interval-ms 5000`，以免破坏现有位置参数。若未来改用嵌套子命令，须同时保留旧入口兼容适配。

**验收：** 独立 DNS 对端验证全部新记录、NXDOMAIN/NODATA、不同顺序/TTL、截断 TCP 回退、多服务器超时隔离、别名/IDN/PTR、连续变更与取消；对畸形压缩指针、超长响应和资源预算做边界测试。DoH/DoT、递归迭代追踪和 DNSSEC 本地验证单列后续，不将 AD 标志直接解释为本地完成 DNSSEC 验证。

### X03：TFTP 选项、大文件与真实设备兼容

**分步范围：** X03-A 实现 RFC 2347 的选项协商及 RFC 2348/2349 的 blksize、timeout、tsize；X03-B 增加经过验证的大文件兼容配置。客户端和服务端分别实现，保留默认 octet、只读、来源限制、流式文件、取消及不覆盖行为。

**协商：** 默认块大小仍为 512，可主动请求更大块；对端忽略选项则按标准回退。验证 OACK、ACK0、请求/响应选项值、重复/未知选项及 option negotiation error。块大小受协议范围、实现内存预算和实际路径约束，不因使用最大块就宣称最高速率；显示实际协商值。tsize 是对端声明，接收仍按实际字节和本地容量控制。

**文件大小与块号：** 协议块号为 16 位。首步可在不回绕的兼容模式下，通过较大块支持超过 32 MiB 的文件，并依据最终块大小计算最大可接受文件，考虑整块结束需要额外零长度 DATA。不能仅删除原大小检查。

块号回绕不是所有设备一致支持的互通保证。X03-B 如提供回绕配置，必须明确双方兼容模式、内部使用更宽逻辑块索引、正确区分旧重复包和新块，且覆盖至少两个回绕周期；未经验证的设备仍保留边界拒绝。windowsize、并发传输、netascii 和续传继续列后续。逐设备记录读/写、协商、大小和哈希，不写“所有路由器固件兼容”。

**结果与验收：** 记录请求/实际选项、逻辑块数、重试、实际字节、吞吐及提交状态；最后 ACK 丢失仍说明远端可能已保存。与至少两个独立 TFTP 对端及真实设备测试：忽略/拒绝选项、异常 OACK、丢 DATA/ACK、不同 TID、零文件、整块长度、大小边界、>32 MiB、启用时跨 65,535 块和取消清理。大文件使用实际数据传输并核对哈希，不用截断/虚构统计代替。

### X04：收藏、现场配置、持久历史、报告与脱敏

**X04-A 收藏及现场配置：** 保存常用目标和工具配置，可按现场/项目命名；收藏工具与收藏目标区分。配置导入导出有独立 schema、大小限制及字段校验，不带秘密、不自动启动任务/服务。只引用凭据需求，重跑时重新输入。B01 的导航偏好可迁入版本化存储，保留旧语言/外观迁移逻辑。

**X04-B 持久历史：** 建议 GUI 使用 SQLite 保存任务索引和结构化结果，原始大量样本/报文放受预算控制的文件；由 core/storage 共用数据结构，Tauri 持有应用数据目录和生命周期。CLI 默认不加入 GUI 历史，后续可显式指定历史目录，不能默默写当前目录。

存储层至少包括 tasks、artifacts、bookmarks、profiles 和版本迁移记录；稳定存储 task_id、工具/schema、脱敏请求、执行状态、结论、起止时间、平台/版本、结果摘要及附件关联。应用重启后将残留 running 标为 interrupted，不假设完成，也不自动重启服务。四十条会话列表与持久历史区分，不能用会话淘汰机制删除所有历史记录。

建议默认保留 30 天/1 GiB 历史预算，附件单独计费并显示清理规则；活动任务、用户固定结果及导出文件按明确策略处理。保存操作事务化，升级迁移前备份可回退；并发 GUI 实例的写入锁和迁移互斥要明确。磁盘不足时停止可选详细记录并提示，不能悄悄丢数据后仍标完整。损坏附件不应让整个应用无法启动；历史删除同步处理受管附件，不能删除用户自选目录中的任意文件。

**X04-C 独立 HTML 报告：** 保留 JSON/PNG，新增无需外部资源的单文件 HTML，包含版本/提交、平台、目标、源信息、工具参数、时间与时区、统计口径、停止/失败状态、证据、解释、限制和脱敏说明。先实现单任务报告，再支持显式选取的排障会话集合，不无界拼接所有历史。

HTML 使用本地 CSS、内嵌 SVG/有限图表或静态表格，不引用 CDN，不执行日志/证书中的脚本。分页附件或超预算结果以清晰截断提示和数据摘要呈现；不能把仅保留预览输出为完整原始记录。PNG 继续注明可见窗口，HTML 可呈现更完整摘要；PDF 暂后续按实际需求加入。

**X04-D 脱敏：** 导出前预览，可选择 IP、主机名、路径、MAC、日志正文；同一个对象映射为一致标识，保留目标间关系。IPv4/IPv6、scope、端口及 URL 分段处理，不能简单正则破坏地址关系。报告别名不能作为可执行重跑目标；secret 字段始终排除，不依赖用户勾选。证书 SAN、SNMP 名称等也可能包含现场名称，纳入预览。默认无正文的历史与可选完整附件分别说明，不能承诺仅靠关键字替换自动清除所有秘密。

**CLI 草案：** 有限任务的 JSON 结果保持标准入口；新增 `hk report <result.json> --output report.html --redact`，只解析支持的 schema，未知版本给出可解释错误，不从导入文件启动网络任务。为文本/JSONL持续任务生成报告时，明确先完成事件归并及完整性验证，不能把任意 JSONL 当成最终结果。

**验收：** 重启/强制退出后状态、搜索/重跑/删除、配置导入、旧格式迁移与回退、并发写入、磁盘不足和损坏附件；包含秘密的金样本验证全部输出不泄漏。中文、长 URL、IPv6、多响应者、Counter64、超长日志、失败/停止/无样本的 HTML/PNG 视觉核验。将报告置于无网络环境打开，核对无外部请求、无脚本注入和统计一致性。

## 8. 实施顺序与工作包

### 8.1 先行验证

在开始对应大功能前，用小型开发原型回答四个问题：macOS 能以何种权限读取连接和邻居；各系统怎样控制 ICMP 分片并获取 MTU 错误；DHCP 如何在不影响系统客户端时正确收发；候选 Rust SNMP 库能否可靠支持计划的 v3 组合。原型结果写入各功能测试报告，不能将实验程序直接作为未经整理的正式依赖。

B02 按当前工作包需要建设，不先重写全部任务系统。X04 的存储和导出协议在早期定稿，完整历史界面和报告随后完成，避免新工具先各自保存一套不兼容数据。

## 9. 测试、平台与发布验收

### 9.1 测试层次

1. **核心行为：** 配置校验、地址/端口展开、协议编解码、状态语义、统计、字节及时间预算；用独立预期和可注入时钟/传输验证，避免只复制实现逻辑。
2. **协议互通：** 使用与被测实现独立的 TCP/UDP、DNS、HTTP/TLS/代理、SNMP、TFTP 和 DHCP 对端；协议成功、拒绝、畸形包、丢包、延迟、重复、乱序、取消均有结果依据。
3. **CLI：** text/json/jsonl、中英文、帮助/退出码、stdin、信号取消、标准输出/错误输出边界、无秘密；机器字段稳定。
4. **GUI：** 分类/搜索/收藏、专属表单和结果、后台任务、四任务限制、导出和错误反馈；浏览器 fixture 与原生 WebView 分别记录。
5. **平台与现场：** 三个发布目标、多网卡、VPN、IPv6、权限、物理休眠/唤醒、真实设备；共享协议测试不能代替本机适配器验收。
6. **产物：** 从安装包或 ZIP 中运行 GUI/CLI/hk，核对版本、资源、架构、退出清理、升级、历史兼容及哈希。

建议新增的协议/原生测试按工作包放入 `crates/hopkit-core/tests/` 和 `scripts/`，例如 scan、discovery、socket、mtr、snmp、pmtu、dhcp、connections、storage、report。每次只运行本次修改相关测试与必要旧功能回归；合入和发布阶段执行完整要求，避免每个小改动无意义地重复长时测试。

### 9.3 性能与正确性门槛

- 有界并发、缓存、结果存储和日志；测试验证数值上限确实生效。四个并发任务下没有饥饿和 UI 长时间阻塞。
- 新增自有网络操作按第 4 节停止目标验证；不可中断的系统查询实测最长延迟并显示原因。
- 扫描/发现至少 4,096 候选或等量受控任务的调度测试，验证无重复、无漏记、计数与落盘一致；不为了测试向公共地址段发探测。
- MTR、DNS 连续查询、SNMP 接口观察、Socket 监听及现有 Monitor 在原生环境至少两小时，记录工作集/CPU/句柄/文件增长和故障恢复。beta 前安排至少一次八小时组合运行，单独记录物理休眠及接口/VPN切换。
- 每份测试证据包含日期、平台/架构、应用版本、提交、参数、独立预期、实际结果及未测范围。发布产物补充实际二进制哈希。
- 不将中间 ICMP 不回应等同转发丢包、不将 UDP send 成功当对端收到、不将未发现地址当空闲、不将超时当精确 MTU、不将多 DHCP Offer 当恶意、不将 WOL 发出当唤醒。

### 9.4 构建和发布门槛

使用仓库固定 Rust 工具链、Node 24 和已有锁文件。每功能合入时按影响运行 `npm run build`、相关 Node/UI 脚本、核心协议/CLI测试；Rust 变化检查格式及静态分析。正式发布前执行 `cargo test --workspace --locked`、全部纳入范围的协议/原生回归、完整 CLI 与桌面构建，再由 `.github/workflows/release.yml` 扩展的新功能验收步骤阻止失败产物进入发布。

发布前维护源码版本、构建版本、工具能力清单、协议 schema、安装元数据和文档的一致性；复查新增依赖的许可证、通知、SBOM 和现有 Wormhole 对应源码分发要求。应用 identifier 的历史迁移、签名/公证和最低系统版本认证不与本次功能版本号绑定，沿用现有边界并明确记录。

每个平台从实际产物验收：安装/解压、`hk --version`、`hopkit-cli --version`、GUI 版本、中文/空格路径、旧工具回归、四分类导航、任务取消/退出、新功能样例、历史迁移、JSON/PNG/HTML。未完成条目不得用“构建成功”替代。
