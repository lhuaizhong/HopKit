## U01 数据与计算边界

`subnet::Config` 明确包含 `operation/input/other/prefix`，拒绝未知字段。CLI 和 GUI 直接调用同一离线核心，计算不调用 DNS、套接字或网络任务调度。CLI 使用原有结果信封；GUI 导出包含 schema 1、实际计算时的请求快照与结果，修改表单后导出不会冒用尚未计算的新输入。

地址运算使用整数，不经 JavaScript 浮点数。`address_count` 和 `host_count` 使用十进制字符串，IPv6 `/0` 为 `340282366920938463463374607431768211456`。普通 IPv4 广播子网展示常见主机范围；`/31` 两个地址计入点到点用途，`/32` 为单地址，两者不输出普通子网广播。IPv6 不扣除首尾地址、广播字段为 null；上述主机数量不代表配置中的实际地址可用性。

拆分在分配结果前检查子前缀及最多 1,024 项；聚合输入最多 1,024 个网段、总文本最多 16 KiB，结果精确覆盖输入集合，保留空洞。非连续掩码、越界前缀、无效 IP、错误比较输入返回 `INVALID_ARGUMENT`。`contains` 真退出 0，假退出 1；参数错误退出 2。

## E01 输入、调度与结果契约

| 参数/资源 | 实际约束 |
| --- | --- |
| 目标 | 数字 IPv4/IPv6、域名、IPv4 CIDR、完整 IPv4 起止地址；CIDR 小于 `/31` 排除网络/广播，`/31` 和 `/32` 保留全部地址 |
| IPv6 | 仅明确地址，不枚举 CIDR；支持数字 scope ID，如 `fe80::1%4`；候选及端点保留 scope |
| 端口 | 1～65,535；逗号和升序范围；统一去重；无开放端口仍为有效完成 |
| 容量 | 最多 4,096 个候选 IP、65,536 个 IP×端口组合；展开后与解析后均校验，不截断成未注明的子集 |
| 并发 | 默认 32、每任务 1～128 个工作线程；同一 GUI/进程扫描共用 128 个连接许可；每端口不新建系统线程 |
| 速率 | 每任务 1～100 次/秒，默认 100；同一进程共用 200 次/秒；等间隔放行，避免突发，公平轮转准备就绪的任务 |
| 超时 | 每次实际建连 100～10,000 ms，默认 1,000；排队时间不计入建连耗时；取消可以打断限速等待与活动建连 |
| 地址族/源地址 | Auto/IPv4/IPv6，源地址必须是数字本机 IP；固定候选与源地址类型必须全部匹配，否则在连接前拒绝 |

每个域名在准备阶段解析一次，使用既有可取消、有期限的系统解析适配器；全部解析和预算校验通过后才发起连接。系统解析最多 4 个后台工作线程，等待每 50 ms 检查取消、最长 5 秒；操作系统解析调用本身可能继续到系统返回，占用的许可届时释放，全部忙时返回资源错误。`scan_target` 事件附输入与候选；运行期间不再次解析。解析失败返回错误，不把失败的名称当成“全部端口关闭”。独立 CLI 进程各有自己的预算，不与 GUI 或其他 CLI 进程跨进程协调。后续发现/MTR 接入时还需要复用此调度能力。

最终 schema 1 数据包含 `resolution_complete/candidates/ports/rows/stats/partial/notes`。每行包含 `address/port/status/elapsed_ms/local_endpoint/remote_endpoint/error`。状态为 `open/refused/timeout/unreachable/local_error/cancelled`；错误保留核心错误码及系统证据。成功连接的实际源端点来自套接字；失败连接无法取得的本地端点为 null，不伪造实际源地址。

`stats` 包含 `total/completed/remaining/interrupted/counts/duration_ms`。中断中的端点不算已完成，剩余数包括中断和未调度项。准备阶段取消尚无法确定总数时，`resolution_complete=false`，`total/remaining=null`、已完成 0，返回明确的部分结果；不把未知总数写成 0。主动停止沿用 `CANCELLED`、CLI 退出 130，最终错误信封仍含部分结果。

`open` 只证明 TCP 建连成功；预设端口用途不等同实际服务身份。`timeout` 不改写为 filtered，拒绝可能来自中间设备。未实现 SYN/UDP 扫描、Banner、指纹或漏洞检测。

GUI 实时事件继续受现有预览预算限制；结束后分页读取完整有界结果，筛选和分页不修改累计数据。JSON 导出包含完整任务结果，非当前页。开放端点的“TCPing →”只预填地址、端口和地址族，不自动发起测试；TCPing 不支持的扫描源绑定会明确提示。两类新配置随 M1 schema 1 白名单保存；不启动任何任务。扫描源 IP 在应用启动时留空，不自动沿用历史绑定，默认跟随系统路由；手动填写、当前会话切换和主动载入现场配置仍支持显式绑定，并可一键恢复默认地址。

## 复现与证据

使用仓库 Rust 工具链、Node 24 与锁文件。新增脚本和本地 TCP 对端不依赖公网扫描目标；产物写入忽略提交的 `test-output/m2/`。

```sh
npm run build
npm run test:preferences
npm run test:monitor-range
npm run test:navigation
npm run test:m1-ui
npm run test:m2-ui
npm run test:wormhole-ui
cargo test --workspace --locked --offline
cargo build -p hopkit-desktop -p hopkit-cli --features hopkit-desktop/custom-protocol,hopkit-desktop/native-test --locked --offline
python3 scripts/m2-integration-test.py
python3 scripts/m2-native-test.py
```

- Rust 单元与集成：输入边界、错误分类、受控 timeout/unreachable、取消、真实 IPv4/IPv6 开放/拒绝、源绑定、域名候选和四任务调度公平性。
- CLI 独立核对：Python `ipaddress` 作为独立计算参考，固定种子生成 39 组子网样本，覆盖 `/0`、`/31`、`/32`、IPv6 `/0`、`/64`、`/127`、`/128` 及非字节前缀；核对包含/重叠、拆分与精确聚合；真实 TCP 对端、JSON/JSONL、退出码和 Ctrl+C 部分结果。
- Vue fixture：子网调用真实 CLI 运算；扫描使用受控 IPC 数据核对 105 行分页、完整导出、手动 TCPing 联动、跨分类取消、保存/重启、收藏、双语及两种外观的 960×680 布局。M1/M2 fixture 使用隔离 Vite 缓存和端口，避免并行验收相互干扰。
- 原生 WKWebView + Rust IPC：离线 IPv6 大整数、真实扫描表单/对端/源绑定、TCPing 联动、四个扫描任务与第五项拒绝、满任务下离线计算、停止全部及部分结果。测试驱动只编译进 debug `native-test` 功能，release 禁止启用。设置 `HOPKIT_NATIVE_TEST_CONFIG` 的验收窗口使用 incognito 存储，避免回环源地址等测试参数写入真实用户配置。
