# M5 开发与验收记录

日期：2026-11-16。基线：`60e3349`（M4 后续修正），源码版本：`0.2.0-dev.6`。对应[技术开发计划书 8.2](HopKit-0.2.0-技术开发计划书.md#82-推荐里程碑)的 **E04 ICMP MTR**。

本轮已交付 Rust 核心、CLI、Tauri 和专家工具专属 GUI，完成 Windows 双栈回环、共享进程四任务与取消、独立 PTR 对端、统计及缺口注入验证。真实隔离路由网络、macOS 原生与物理休眠仍需现场验收；单元拓扑和回环证据不能替代这些门槛。

## 使用与结果语义

在专家工具搜索 **MTR / 持续路由**，配置目标后手动启动；搜索、切换分类和载入现场配置不发送探测。表格展示每 TTL 的发送、响应、超时、中断、未回应率、有效 RTT 最近/最小/平均/最大及抖动。响应地址可展开每个响应者的独立统计，变化时间线记录 UTC、轮次、TTL 与前后响应地址。

```sh
hk mtr example.com --cycles 100 --interval-ms 1000 --max-hops 30 --format jsonl
hk mtr ::1 -6 --source ::1 --cycles 10 --format json
hk mtr 192.0.2.1 --cycles 0 --duration 60 --ptr-server 192.0.2.53 --format jsonl
```

首版仅 ICMP IPv4/IPv6，不调用外部 mtr。每轮从 TTL 1 开始，每 TTL 一个探测，收到目标本身 Echo Reply 后结束该轮；无目标响应时遍历最大 TTL。目标地址首次解析后固定，不在每轮重新解析。显式源 IP 采用平台适配器绑定；Auto 配合源 IP 时按源地址族解析，不默默换源；IPv6 数字 scope 由已有适配器保留。源绑定与固定出口接口是不同能力，不宣称固定接口。

**目标到达率**为到达目标的完整轮次数 / 完整轮次数。中间跳响应率按该 TTL 已完成探测计算，中断不进入分母。中间跳未回应不等于转发丢包；有效 ICMP 错误算响应但不算目标到达。有效 RTT 才进入延迟统计；超时、停止中的调用、本机权限错误不会填充零延迟。

抖动为相同 TTL、相同响应者的连续有效 RTT 差绝对值均值（ms），记录有效相邻对数；跨超时、缺口、响应者变化或某 TTL 本轮未被观测时断开计算。没有有效相邻对为 null / —。这是 RTT 变化指标，不是单向抖动；没有 P95。多个响应者表示观测集合，不拼接成已证实的唯一物理路径，不把 TTL 间 RTT 差当作链路延迟。ECMP、往返不对称及 ICMP 限速均影响解释；没有 Paris traceroute 保证。

GUI 切换工具后仍可从全局任务中心停止，停止和失败保留累计统计及部分结果。支持中英文、两种外观、工具收藏、命名现场配置和参数导入导出；配置恢复不自动运行，重启时源绑定回到系统路由，手动载入现场配置可恢复显式源。JSON 导出含累计统计和有界预览/淘汰说明；PNG 沿用可见窗口范围。

## 契约、调度和边界

- 稳定 ID `mtr`，action `icmp`，独立嵌套 `mtr::Config`，结果/schema 为 1；Rust 独立验证 tool/action/config、数字边界与目标。旧 Ping/Trace 请求与 schema 不变。
- 核心事件 `mtr_sample`、`mtr_snapshot` 带递增 `event_seq`；CLI JSONL 以 `mtr_sample` 和压缩的 `mtr_stats` 流式输出，最后 `finished` 带完整累计结果与请求快照。Tauri 在事件队列之外保留最新完整统计，150 个通用预览事件淘汰不会丢失逐跳统计。
- 退出 0：至少一个完整轮次到达目标；1：执行完成但没有到达；2：参数错误；3：本机权限/能力/资源；4：文件/输出错误；130：主动取消。`--strict` 要求所有完整轮次到达，且没有中断探测；不以中间 TTL 不响应判失败。JSON 必须有有限轮次或时长；文本/JSONL 允许持续到 Ctrl+C。

| 参数/资源 | 默认与边界 |
| --- | --- |
| 轮数 | 默认 100；0 持续；最多 1,000,000 |
| 时长 | 默认 0 不限制；最多 86,400 秒，与轮数先到者结束 |
| 轮次最小起点间隔 | 默认 1,000 ms；100～60,000 ms；上一轮慢时不排队、不补造轮次或样本 |
| 单探测超时 | 默认 1,000 ms；100～1,000 ms；Windows 同步调用以此约束取消延迟，Unix 每 50 ms 检查取消 |
| 最大 TTL | 默认 30；1～64 |
| 每任务探测速率 | 默认 20/s；1～100/s；所有 TTL 均计入，复用 Scan/Discovery 的公平调度器 |
| 进程共享预算 | 200 次/s、128 个探测许可；GUI 最多四个任务，独立 CLI 进程各有自己的预算 |
| 预览 | 最近 256 个样本、256 次响应者变化、256 个缺口；各自淘汰计数独立 |
| 响应者 | 每 TTL 最多保留 16 个地址及其独立统计；超限响应仍计入全 TTL 累计并增加 untracked_responses |
| GUI 快照 | 通常每 250 ms 或更慢，长轮次期间至少每约 1 秒按探测进度更新；CLI 不重复完整快照 |
| PTR | 默认禁用；显式数字解析器启用，每任务单独工作线程，进程合计最多两个活动查询；任务队列/完成队列各 16、最多 256 地址，每地址最多 4 个名称/253 字符 |

PTR 复用原有严格 DNS 解码器，以独立 UDP、300 ms 超时、系统路由查询；不跟随 ICMP 源绑定、不使用隐式公共解析器、无 TCP 回退，队列满、超时、失败、停止中的查询各有状态。PTR 名称不作为 ICMP 可达性或设备身份的证明，不覆盖数字响应地址。远端名称由 Vue 文本插值/CLI 转义展示。未来 DNS 高级能力仍归 M9。

采样间隙同时比较墙钟与单调时钟；等待/调用超出预期至少 2 秒时记录 `suspend_or_scheduler_delay`，不将其断言为物理休眠。发生于调用内的探测计为 interrupted，重置抖动连续性；恢复后重新开始轮次，不计算停顿期间的“应发包”，不补造超时。系统时钟向后调整单独不产生丢包。时长到期可在最后一个已发探测结束后收尾，最坏约一个超时加调度/清理时间。

Windows 使用每次新建的 IP Helper ICMP handle，由系统匹配请求/响应；Windows 本机调用失败转结构化本机错误，不算网络超时。macOS 使用现有 datagram ICMP，匹配地址族、目标、ID、序号及已引用的正文；此次补强原适配器对可得引用正文的验证。Linux 延续 ping socket 与错误队列匹配。没有新增第三方依赖。

## 待现场验收

- 实际隔离路由网络的 IPv4/IPv6 多跳、TTL 引用匹配、路由变化及真实 ICMP 限速；模拟拓扑和回环不能代替。
- macOS Intel/Apple Silicon 原生 ICMP/源绑定与权限、Linux CLI 原生环境；本机没有可运行的 macOS 或 WSL 环境。
- 物理休眠/唤醒、接口/VPN 切换和系统时间变化；当前缺口阈值为启发式检测，不承诺识别所有短暂休眠。
- 多种真实路径的长时/八小时组合运行，以及三平台实际安装包验收。此次没有发布资产、安装包或新标签。
