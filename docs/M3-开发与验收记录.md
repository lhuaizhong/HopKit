# M3 开发与验收记录

日期：2026-11-15。开发基线：`066953c`（M2）；本次源码：`0.2.0-dev.4`。对应[技术开发计划书 8.2](HopKit-0.2.0-技术开发计划书.md#82-推荐里程碑)的 E02 设备发现、邻居信息与冲突线索。

## 交付范围

- `discovery` 稳定 ID、嵌套 Config、schema 1 结果/事件、参数快照、能力查询。CLI 为 `hk discover`；GUI 位于专家工具的 Discovery / 设备发现。
- IPv4 CIDR、完整起止地址、多段非连续候选；IPv6 仅明确候选，保留数字 scope，不遍历 IPv6 前缀。接口列表只查询本机；“填入此网段”只填表单，启动须明确操作。留空目标只读取邻居缓存。
- ARP、ICMP Echo 和最多 8 个 TCP 候选端口，可组合或单选，默认三种方法一起启用。TCP 建连成功和明确拒绝分别记录；拒绝可能来自中间设备，不证明服务开放。ICMP 错误不作为目标 Echo 响应。未响应统一为 unknown，不能推断离线或空闲 IP。
- ARP 只对 IPv4 直连网段发起：先匹配本机接口地址/掩码及所选源地址，再检查当前路由的接口和网关；经网关、VPN 隧道、IPv6、回环、本机地址及网络/广播地址跳过，不发送 ARP。macOS 使用 Ethernet BPF 广播请求并验证应答双方 IP/MAC、操作码和接口；Windows 使用 `GetBestRoute2/GetIfEntry2` 检查直连以太网，再调用 `ResolveIpNetEntry2`（2026-11-19 修正，替代可能返回旧缓存的 `SendARP`）。仅实际解析应答计入本次响应，能发现禁 Ping 的终端。
- 与 M2 scan 共用一个进程内公平调度器：每任务默认 32、最大 128 个工作线程，默认/最大 100 次/秒，共享最多 128 个探测许可和 200 次/秒。PTR 查询同样计入共享放行预算。独立 CLI 进程不共享预算。
- macOS 用系统 `/usr/sbin/arp -an` 和 `/usr/sbin/ndp -an` 只读查询；固定参数、C locale、每项 5 秒、512 KiB 输出上限、取消时终止并回收子进程。Windows 使用 `GetIpNetTable2/FreeMibTable`，保留接口索引与邻居状态；最多两个后台查询线程，前台每 50 ms 检查取消、5 秒超时。系统调用可能延后完成，线程许可在实际返回时释放。Linux 继续支持主动 CLI 探测，邻居适配器明确 unsupported。
- 探测前后分别采集邻居快照，按精确地址和链路归属；不把跨路由目标关联到网关 MAC。缓存 state、MAC、接口、来源、采集时间与 before/after 均保留。macOS ARP 动态条目年龄不可得，标记 `cached_age_unknown`。系统占位 MAC `02:00:00:00:00:00` 记为未知，同时提示部分可见。
- 同 IP、同接口索引和名称下的不同 MAC 形成 `mac_change_hint`，保留两份证据。跨接口的 MAC 不形成冲突提示；共享虚拟/Proxy MAC 本身也不触发。提示注明 Proxy ARP、VRRP、网卡切换等可能性，不作冲突定论。
- PTR 是响应后的可选阶段，最多 4 个工作线程，必须显式指定数字 DNS 服务器，不默认查询公网。UDP 返回最多 4 KiB、最多 16 个名称，每项 253 字符，100～1000 ms 超时；验证 DNS ID、question/type/class。截断回复明确报错，不进行可能阻塞的 TCP 回退。超时、NXDOMAIN、无 PTR 和名称不影响主动响应事实；名称不证明设备身份。
- GUI 提供响应/未知统计、逐方法证据、缓存与名称来源、MAC 变化提示、筛选和每页 50 项，主动发现仅显示响应设备并按 IP 数值排序，MAC 直接展示；显式缓存模式只显示有 MAC 的条目且注明缓存。JSON 导出保留全部候选和完整 task.result，运行中预览明确有界。任意远端文本使用 Vue 转义展示。
- 结果可手动送往 Scan、Ping、TCPing、网络排障/Web；传地址和适用地址族、scope、端口、源 IP。Scan/Check 保留适用源绑定，Ping/TCPing 不支持源绑定时提示。传递不启动新任务。尚未实现 SNMP、独立 HTTP/TLS 工具，因此不注册虚假入口。
- 保存/恢复现场配置、搜索/收藏、双语、两种外观和全局任务中心沿用 M1。启动应用清空自动恢复的源 IP/接口，手动载入现场配置可恢复显式选择。

首轮未响应且 ICMP 超时的目标，在首轮完成后追加一次 ICMP 复核，使用相同源地址、共享并发/速率和取消机制。成功目标、仅 TCP/ARP 任务、本机能力错误不复核。两轮证据均保留，探测统计包含实际追加的探测。

运行中发现快照按 IP 保留（最多 4096 个），与 150 条通用事件队列独立；后续未响应事件不会挤掉已发现设备。

## 契约与边界

Config 包含 `targets/interface/methods/ports/timeout_ms/concurrency/rate/source/name_lookup/dns_server`，拒绝未知字段和 tool/action/config 不匹配。输入最多 4096 个候选、65536 个探测组合；CIDR 小于 /31 排除网络/广播，/31、/32 保留全部地址。范围、端口、scope、源地址族、接口归属在探测前校验，候选按规范地址去重。

接口选择用于获取源 IP 和 IPv6 scope；**不等同强制固定接口路由**。混合地址族按目标选接口对应地址，无匹配地址时报错。源绑定错误保留在逐次 observation，不默默换出口。PTR 使用到所选解析器的系统路由，界面与结果说明此行为。

Result 为 `rows/stats/neighbor_sources/errors/partial/limitations`。每个 Device 包含 `responded/first_response_at/last_response_at/observations/neighbors/name/mac_change_hint`；Stats 区分 `candidates/responders/unknown` 和探测 `planned/completed/remaining/duration_ms`，不由界面预览反推。取消在 CANCELLED 错误信封中携带完整部分数据；已发起但取消的探测不计 completed，未响应候选保留为 unknown。

CLI：正常完成（含零响应）退出 0；参数错误 2；本机探测/能力/资源错误 3；取消 130。全部主动探测受本机错误影响且无响应时返回 `LOCAL_PROBE_FAILED`；部分方法不可用而其他方法有证据时保留 partial。邻居适配器错误单独列出；缓存读取完全失败时不返回伪造的空成功。

主动 ARP 支持 Windows/macOS，能力表为 partial：macOS 需 `/dev/bpf*` 读写权限及可见的接口 MAC，缺失时显示具体错误，ICMP/TCP 继续执行；不安装提权助手或修改设备权限。Windows 同步 `ResolveIpNetEntry2` 由最多 32 个后台线程承载，单次超时/取消返回后，系统调用与全局探测许可仍保持至实际返回，防止资源失控。主动 ND、RFC 5227 ARP Probe、离线 OUI/厂商数据尚不提供。系统可能因权限、隐私或网络环境省略邻居；空缓存不代表空网络。

### 初轮现场记录与平台未测范围

本机直接系统查询可见真实 ARP/ND 条目，但从当前调试 CLI 进程得到的邻居输出只包含部分 ND，部分 MAC 为系统占位值；代码保留限制并将占位值视为未知。对当前网关的单目标接口绑定尝试只有超时，诚实保留 unknown；未证明真实设备主动响应、完整邻居可见性或系统隐私设置的成因。该记录不把回环通过当成多网卡、VPN、跨路由及真实冲突验证通过。

本次追加验证：ARP-only 的非直连 IPv4、IPv6、回环目标均返回 `skipped_not_on_link`，text 不显示未知 IP，JSON 保留全部证据。本机单网关测试验证了路由查询路径，但当前进程受系统 MAC 可见性/BPF 权限限制；无缓存的 sudo 授权，未执行管理员 ARP 收发测试。因此真实禁 Ping 终端发现和 MAC 收发尚待有 BPF 权限的环境验收；受控 ARP 应答与界面测试通过不替代现场验证。

## 2026-11-19 Windows ARP 全部超时修复

在 Windows 原生环境使用候选 `10.232.129.3-10.232.129.30`、方法 `arp,icmp`、默认超时 500 ms 复现：28 个候选的 ARP 均返回 `TIMEOUT: System adapter timed out`，整次发现耗时 6454 ms。接口枚举调用了完整的 PowerShell/CIM 网络概览，超过其 5 秒查询上限；查询失败被 `OnceLock` 共享给所有候选。即使查询成功，原先在枚举前启动的 500 ms 计时也可能已经耗尽，导致尚未发包就超时。

修正：设备发现改用 `GetUnicastIpAddressTable/GetIfEntry2` 读取地址、掩码和接口别名，保留 IPv6 link-local scope，只提供活动且地址状态可用的接口；接口准备完成后才启动 ARP 等待计时。Windows 主动探测改用 `ResolveIpNetEntry2`，强制重新解析指定地址和接口，并校验返回的 IP、接口及 MAC 长度；保留后台调用的并发和取消预算。接口不存在的错误不再归为报文超时。GUI、CLI 共用这一核心实现。

现场复测（本机接口 8，地址 `10.232.129.25/24`）：

| 配置 | 结果 |
| --- | --- |
| 原地址段，`arp,icmp`，500 ms | 15 个 ARP reply，12 个 ARP timeout，本机 `.25` 跳过；组合发现 16 个响应者；总耗时 1463 ms |
| 原地址段，`arp`，`--interface 8`，500 ms | 15 个 ARP reply（均附本次解析 MAC），12 个 timeout，本机地址跳过；总耗时 829 ms |
| `.3`，仅 ARP，中文接口别名 `以太网`，源地址 `.25`，100 ms | ARP reply，返回对应 MAC，ARP 耗时约 16 ms |
| `127.0.0.1`、`::1`，仅 ARP | 跳过，不发起原生 ARP |

未响应仍为未知，不推断设备离线。新增回归覆盖慢接口初始化不占用报文超时、原生接口地址/中文别名/IPv6 scope/状态/取消，以及 ARP IP/接口/MAC 校验和错误分类。core 全部 118 项单元测试通过（其中发现相关 13 项）；CLI 和嵌入前端的 Windows 桌面调试程序均构建成功。现场原始输出位于本机 `test-output/arp-fix/{before,after,arp-only,skipped,source-bound}.json`（忽略目录，不提交设备信息）。
